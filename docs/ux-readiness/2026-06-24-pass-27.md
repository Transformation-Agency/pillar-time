# UX Readiness Pass 27

## Scope
- Area: Settings credential save failures for model provider, X API, and Telegram delivery.
- Goal: keep setup failures visible and recoverable inside the modal where the user is working.

## Finding
- Some Settings credential save handlers closed only on success, but failures were not consistently surfaced in the modal.
- A first-run user with a bad key or backend validation failure could be left without clear local recovery copy.
- This is especially rough for pasted credentials because the user needs to correct the value in place, not hunt through logs.

## Change
- Converted model provider save to `async` with local error handling.
- Converted X API save to `async` with a visible modal warning on failure.
- Converted Telegram setup save to `async` with a visible modal warning on failure.
- Kept modals open on failure so pasted inputs remain available for correction.
- Added guardrail tests for the save handlers and visible warning messages.

## Verification Plan
- `npm test`
- `npm run build`

## Follow-Up
- In browser QA, submit invalid model, X, and Telegram credentials and confirm each modal remains open with a visible warning.
