# UX Readiness Pass 22

## Scope
- Area: Google Calendar connector modal.
- Goal: prevent silent loss of calendar-selection changes.

## Finding
- After changing selected Google calendars, closing the modal with X, backdrop click, or Cancel immediately reset the selection.
- There was no warning that the daily planning inputs would keep using the previously saved calendars.
- This is high-friction because primary vs shared calendar selection is central to the time-management logic.

## Change
- Added a dirty-state confirmation to the shared Google Calendar modal close handler.
- The confirmation explains that unsaved calendar choices will be discarded and previous calendars remain active.
- Because the close handler is shared, X, backdrop close, and Cancel now all protect unsaved selections.
- Added a guardrail test for the close handler and its three close entry points.

## Verification Plan
- `npm test`
- `npm run build`

## Follow-Up
- In browser QA, change one calendar checkbox, click outside the modal, cancel the confirmation, and confirm the modal stays open with the changed checkbox still visible.
