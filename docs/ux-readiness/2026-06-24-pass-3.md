# UX Readiness Pass 3: Telegram Delivery Ambiguity

Date: 2026-06-24
Branch: main follow-up

## Finding

Telegram delivery can succeed while Pillar Time records a timeout waiting for the Telegram API acknowledgement. The backend soft-timeout fix is present in the installed bundle, but the running backend process had started before the fixed code was loaded.

Observed evidence:

- Installed bundle contains `deliverBriefToTelegramWithSoftTimeout`.
- Old backend process started before the restart and had saved recent artifacts with `Telegram delivery timed out after 45 seconds`.
- User confirmed the Telegram message was delivered.
- After quitting and reopening Pillar Time, the backend restarted on port `42818` from the installed `0.2.3` bundle.

## Fix

- Brief list delivery badges now classify Telegram timeout or pending-ack states as `Check Telegram`.
- Normal saved briefs still show `Saved`.
- Delivered briefs still show `Delivered`.
- Failed workflow runs still show `Failed`.

## Verification

- Pillar Time was restarted and the backend re-bound port `42818`.
- `npm test`
- `npm run build`

## Remaining Risk

Old artifacts that already saved hard-timeout text still contain that raw historical delivery object, but the UI no longer hides those ambiguous Telegram outcomes behind a plain `Saved` badge.
