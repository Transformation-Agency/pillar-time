# UX Readiness Pass 15: Onboarding Exit Failure Feedback

Date: 2026-06-24
Branch: `ux-production-readiness-pass-15`

## Finding

The onboarding exit actions had weak failure recovery:

- `Skip and set up manually` called the backend without a local error handler.
- `Finish onboarding` caught errors, but sent them to a source-setup message that is not visible from the review/exit area.

Impact: if the local backend rejects or fails during first-run exit, a user can click the exit action and see no useful feedback. That is exactly the kind of first-run trust break that makes a desktop app feel unreliable.

## Fix

- Added a dedicated onboarding action message for exit failures.
- Wrapped both `Finish onboarding` and `Finish later` / skip paths in explicit `try/catch` handling.
- Rendered the failure message in the onboarding shell so it is visible from any step.
- Added a guardrail test so these paths do not regress to silent failure.

## Verification

- `npm test`
- `npm run build`

## Recommended Follow-Up

Add a rendered onboarding test that mocks `/api/onboarding/skip` and `/api/onboarding/complete` failures and verifies the visible recovery copy.
