# UX Readiness Pass 14: Backend Connection Recovery

Date: 2026-06-24
Branch: `ux-production-readiness-pass-14`

## Finding

If the frontend failed to load `/api/state`, the app showed a dead-end boot message: `API error: ...`. There was no retry button, and the stored error was not cleared after a later successful refresh.

Impact: after a local backend restart, temporary port handoff, or desktop startup race, a real user could see stale failure copy and have no obvious in-app recovery action.

## Fix

- Clear the boot error after a successful state refresh, including the fallback path where optional runtime checks fail but `/api/state` succeeds.
- Replace the terse boot text with a local-backend recovery message.
- Add a `Retry connection` button wired to the existing refresh function.
- Added a guardrail test for stale error clearing and the retry affordance.

## Verification

- `npm test`
- `npm run build`

## Recommended Follow-Up

Add a rendered app test that mocks `/api/state` failing once, then succeeding, and verifies that the boot error clears without reloading the window.
