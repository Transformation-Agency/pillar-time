# UX Readiness Pass 28

## Scope
- Area: Planner task and important-date capture forms.
- Goal: make local planning captures visibly recoverable when a save fails.

## Finding
- Planner task and important-date forms used promise chaining that only cleared the form on success.
- If the backend rejected a save or the local API was temporarily unavailable, the user got no visible confirmation or recovery cue.
- This matters because tasks and important dates are core inputs to the executive-day ranking engine.

## Change
- Added a local Planner status message.
- Converted task creation to `async` with explicit success and failure copy.
- Converted important-date creation to `async` with explicit success and failure copy.
- Left typed input intact on failure so the user can retry without reconstructing the entry.
- Added guardrail tests for visible Planner capture save messages.

## Verification Plan
- `npm test`
- `npm run build`

## Follow-Up
- Browser QA should submit Planner entries with the backend available and unavailable to confirm the message is visible in both success and failure states.
