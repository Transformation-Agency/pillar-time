# UX Readiness Pass 13: Help Menu Keyboard Recovery

Date: 2026-06-24
Branch: `ux-production-readiness-pass-13`

## Finding

The header Help menu includes update status and update actions, but its trigger did not expose popup state and the open menu did not close on Escape.

Impact: keyboard and assistive-technology users had weaker feedback around whether the update/help menu was open, and one common keyboard recovery path was missing.

## Fix

- Added `aria-haspopup="menu"`, `aria-expanded`, and `aria-controls` to the Help trigger.
- Added an id and accessible label to the Help/update menu.
- Added Escape-key dismissal while the menu is open.
- Added a guardrail test for the menu semantics and keyboard listener cleanup.

## Verification

- `npm test`
- `npm run build`

## Recommended Follow-Up

Add rendered keyboard-navigation coverage for the header, including opening Help, tabbing through update actions, pressing Escape, and returning focus to the trigger.
