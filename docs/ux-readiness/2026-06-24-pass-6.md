# UX Readiness Pass 6: Settings Health Check

Date: 2026-06-24
Branch: `ux-production-readiness-pass-6`

## Finding

Settings showed an `All systems operational` panel even when optional connectors or runtime dependencies could be degraded. Its `Run health check` button did not run anything.

Impact: a real user could trust a false green state, click a dead health-check control, and still not know whether missing Calendar write scope, Linear, model, Telegram, FFmpeg, or Whisper state affected workflows.

## Fix

- Renamed the panel to `Local health check`.
- The panel now summarizes current warnings from model, Calendar, Linear, Telegram, update, FFmpeg, and Whisper state.
- The button now refreshes FFmpeg/STT runtime checks and app state.
- The copy no longer says all systems are operational unless current state supports it.
- Added a guardrail that prevents reintroducing the misleading copy or dead health-check affordance.

## Verification

- `npm test`
- `npm run build`

## Recommended Follow-Up

Add a rendered Settings test that exercises `Run health check` with mocked runtime endpoints and verifies busy, success, and failure states.
